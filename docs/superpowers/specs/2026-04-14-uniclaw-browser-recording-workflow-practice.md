# UniClaw 自动化录屏测试工作流实践

- 日期：2026-04-14
- 目标页面：`https://uniclaw.bitmiracle.cn/chat`
- 适用场景：验证“人工启动录屏 + AI 自动化操作网页”这条素材采集链路，并将其沉淀为可交给其他 agent 复用的工作流资产。
- 适用环境：Windows 11、本地可视浏览器、已安装 `browser-use`、系统存在 `Snipping Tool`，并且用户已将 **Windows Game Bar 录屏** 绑定为快捷键 `Alt+\`。

## 1. 文档目标

本文档不只是记录一次临时测试，而是把这次从“打开页面、登录、启动录屏、自动化操作产品、得到真实录屏素材”的完整过程沉淀成一份可复用工作流资产。

后续任何 agent 在需要录制 Web 产品演示素材时，都可以优先复用本文档中的流程，而不必再次从零摸索：

1. 如何打开目标产品；
2. 如何接管登录后的页面；
3. 如何在 Windows 11 上拉起录屏；
4. 如何在录屏状态下执行一轮稳定的自动化产品功能测试；
5. 如何记录测试结果并将录屏文件接入后续配音、字幕和 Remotion 剪辑流程。

## 2. 本次实践的核心结论

本次实践已经验证了一条**现实可行、足够稳定、可被复用**的最小采集链路：

```text
可视浏览器打开目标页面
-> 用户手动登录
-> AI 读取登录后页面状态
-> AI/人工共同完成录屏启动
-> AI 自动化操作主要功能
-> 用户停止录制并保存视频
-> 录屏文件进入后续视频后期流程
```

这条链路的重要意义在于：

- 不要求浏览器自动化和录屏都完全无人值守；
- 不要求配音逐步对应页面上的每个操作；
- 先拿到“真实录屏素材”，再进入后期处理；
- 足够适合作为 `auto-video` 当前阶段的素材采集工作流。

## 3. 实践环境与前置条件

### 3.1 页面与账号前提

- 页面地址：`https://uniclaw.bitmiracle.cn/chat`
- 用户可手动完成登录
- 登录后能进入 UniClaw 主页

### 3.2 工具前提

本次实践实际使用的能力包括：

- `browser-use --headed`：可视浏览器自动化
- Windows 11 `Snipping Tool`：录屏尝试与录屏准备态验证
- Windows Game Bar：实际成功启动录制

### 3.3 本次验证后确认的录屏优先级

基于实测结果，推荐优先级如下：

1. **Windows Game Bar 自定义快捷键录屏**：当前最稳、最适合这条流程
2. **Snipping Tool**：可用于验证和人工辅助，但不建议作为主要录屏技术方案

## 4. 完整实践过程

## 4.1 打开目标产品页面

首先使用可视浏览器打开 UniClaw 聊天页。

目标：

- 用户能够看到浏览器窗口；
- 后续录屏可以直接覆盖这个窗口；
- AI 的自动化操作过程可被用户实时观察。

结果：

- 页面成功打开；
- 浏览器为可视模式；
- 页面最初显示登录相关内容。

### 4.2 用户手动完成登录

登录阶段由用户手动完成。

原因：

- 登录通常包含手机号、验证码等敏感操作；
- 手动登录更稳，也更适合内部测试；
- 自动化应尽量集中在可重复功能路径上，而不是把时间浪费在账号接入上。

结果：

- 用户完成登录；
- 页面进入登录后主页；
- AI 能继续读取并操作页面。

### 4.3 AI 识别登录后主页结构

登录后，AI 读取页面状态并识别出关键可交互区域。

识别到的主要区域包括：

- 左侧导航：`Claws`、`Skills`、`收藏`
- `新建实例`
- 主输入区（聊天发送区域）
- 文件上传入口
- 快捷能力按钮（如 `帮我写作`、`PPT`、`数据分析` 等）
- `我的 Claw` 工作区入口

意义：

- 证明登录后业务页面可被自动化工具读取；
- 后续能围绕这些区域做自动化录屏测试。

### 4.4 首轮录屏尝试：Snipping Tool

接着尝试调用 Windows 11 系统自带 `Snipping Tool`。

已验证成功的部分：

- 可以通过系统命令启动 `Snipping Tool`；
- 用户能看到其窗口；
- 在尝试切换后，曾成功进入录屏准备态；
- 用户实际看到了：
  - 顶部“开始录制”按钮
  - 区域选择框

但也验证出明显限制：

- 快捷键触发和 GUI 控制不稳定；
- `Win + Shift + R` 这类系统级快捷键难以稳定模拟；
- 某些尝试会误触系统其他窗口；
- 适合人工辅助验证，不适合长期作为标准录屏引擎。

### 4.5 第二轮录屏尝试：Windows Game Bar

后来用户说明：

- 已经把 **Windows Game Bar 录屏功能** 绑定到快捷键：`Alt+\`

AI 随后尝试发送该快捷键。

结果：

- 用户确认**已经开始录制**；
- 这说明在当前环境下，`Alt+\` 这条 Game Bar 录屏路径是成功的。

这是本次实践中最关键的录屏结论：

> 在当前 Windows 11 本机环境下，借助用户预先配置好的 `Alt+\` Game Bar 录屏快捷键，可以成功进入实际录制状态。

## 5. 录屏状态下完成的 UniClaw 功能测试

在确认已开始录制后，继续对 UniClaw 做了一轮自动化测试，目标是录到一段“真实且有代表性”的产品操作素材。

### 5.1 聊天主链路测试

操作：

- 在主输入框发送消息：
  - `你好，请用一句话介绍你能做什么`

结果：

- 页面成功进入会话态；
- AI 成功返回回答；
- 证明聊天主链路可用。

这是最基础也最关键的一条产品功能路径。

### 5.2 Skills / Claws 导航测试

操作：

- 进入 `Skills`
- 再进入 `Claws`

结果：

- `Skills` 页面显示技能广场和多种能力卡片；
- `Claws` 页面显示可发现与使用的 Claw 能力内容；
- 页面导航可正常切换。

### 5.3 新建实例流程测试

操作：

- 点击 `新建实例`
- 在弹窗中选择 `官方 Claw`
- 填写实例名称：`录屏测试实例`
- 点击 `创建实例`

结果：

- 创建动作被成功接收；
- 页面返回清晰提示：
  - **已达到当前计划的实例上限（2 个），请升级计划以创建更多实例**

结论：

- 新建实例流程本身是通的；
- 当前是业务限制而不是交互故障；
- 这是一个很适合出现在演示录屏中的“真实产品反馈场景”。

### 5.4 收藏页测试

操作：

- 进入 `收藏`

结果：

- 页面成功展示收藏页；
- 能看到搜索框；
- 当前为空收藏状态；
- 页面有明确空态提示。

结论：

- 收藏页入口与空态交互正常；
- 可作为后续测试收藏动作前后的对比页面。

### 5.5 我的 Claw 工作区测试

操作：

- 进入 `我的 Claw`
- 在其中再次发送一条测试消息：
  - `请帮我总结一下今天适合测试的 3 个 UniClaw 功能`

结果：

- 页面成功进入该工作区的任务执行流程；
- AI 完成任务并输出结果；
- 页面展示了：
  - 输入内容
  - 子 Claw / 子任务执行痕迹
  - 输出内容
  - 过程信息

结论：

- `我的 Claw` 的任务执行链路可用；
- 平台具备“任务 -> 执行 -> 输出”的核心工作流；
- 对于演示视频来说，这一段非常有价值，因为它比单纯的聊天回答更能体现平台能力。

## 8. 复用建议：后续 agent 应如何执行这条工作流

后续其他 agent 如果要复用这份工作流资产，建议直接按下面的顺序执行。

### 8.1 推荐执行步骤

```text
1. 用 browser-use --headed 打开目标产品页面
2. 等待用户手动完成登录
3. 用 browser-use state 读取登录后页面结构
4. 让用户确认录屏快捷键是否已配置
5. 优先使用 Windows Game Bar 快捷键（当前实测为 Alt+\）启动录制
6. 在用户确认“已经开始录制”后，再开始自动化产品操作
7. 优先录制以下主链路：
   - 聊天发送与回复
   - 导航切换（Skills / Claws / 收藏）
   - 新建实例
   - 我的 Claw 任务执行
8. 如果页面有业务限制（如套餐上限），不要回避，应保留真实反馈
9. 测试结束后由用户手动结束录制并保存视频
10. 将视频文件纳入 runs/ 或后续视频编辑输入目录
```

### 8.2 对 agent 的关键要求

复用本工作流时，agent 应遵循以下原则：

- 优先使用**可视浏览器**，不要默认 headless；
- 登录阶段默认由用户手动完成；
- 不要假设系统级快捷键都能稳定模拟；
- 一旦发现某条录屏路径成功，应优先复用，不要继续盲试更复杂的方案；
- 自动化测试应优先覆盖“用户看得懂”的主要功能路径；
- 页面真实业务限制（例如实例数上限）也是有效演示素材，不应视为测试失败。

## 9. 对 auto-video 的直接启发

本次实践证明，`auto-video` 的素材采集层当前完全可以采用下面的现实策略：

- 浏览器操作：`browser-use` / Agent Browser
- 登录：人工完成
- 录屏：优先 Game Bar 快捷键，`Snipping Tool` 仅作为辅助备选
- 自动化执行：AI 完成主链路操作
- 输出：真实录屏文件 + 可选页面状态/事件摘要

这足以支撑后续：

- AI 配音
- 字幕生成
- Remotion 成片

换句话说，当前项目不需要等待“全自动录屏能力”完备，已经可以先把“真实产品录屏 -> 后期自动成片”这条链路推进下去。

## 10. 最终结论

本次已经沉淀出一条可交给其他 agent 直接复用的工作流资产：

**Windows 11 + 可视浏览器 + 手动登录 + Game Bar 快捷键录屏 + AI 自动化操作 UniClaw 主要功能 + 录屏素材进入后期流程。**

这条工作流的优点是：

- 稳定
- 简单
- 成本低
- 贴合当前项目阶段
- 能快速产出真实可用的演示素材

因此，它应被视为当前 `auto-video` 项目的优先素材采集实践路线。
